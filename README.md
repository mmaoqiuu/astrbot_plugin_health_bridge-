# 小狗健康 (Puppy Health Bridge) · 小回的健康守护

> 插件名: `astrbot_plugin_health_bridge`  
> 目标版本: AstrBot **v4.25.1**+

让 AstrBot 接入 iPhone 与 Apple Watch 的健康数据，开辟独立的 HTTP 数据通道。实时记录步数、心率、血氧、睡眠分期、活动状态、女性生理期及身体症状，并在日常对话中让小回自然了解你的身体状态，适时带来温柔的主动关怀。

**优势**:
- 🍏 **原生生态接入**：支持 iPhone 快捷指令免费上报，或 Health Auto Export App 全自动后台 REST API 同步。
- 🔒 **端到端隐私安全**：数据保存在 AstrBot 本地数据目录，独立轻量端口监听，支持自定义或自动生成安全 Token。
- 💬 **沉浸式伪造注入**：主动关怀完整走 OneBot 对话管线，保留人格世界书、上下文记忆与专属羁绊，拒绝机械预设模板。
- 📊 **专属看板前端**：内置手机端适配的 Web 数据看板，四宫格概览与经期状态一目了然，点缀兔球球与星际小宝。

---

## 🧭 原理

iPhone / Apple Watch 记录身体指标后，通过手机自动化（快捷指令或 App）定时将健康数据 POST 上报给服务器。插件接收并增量合并存储，角色模型按需读取或在后台触发异常关怀。

```
Apple Watch / iPhone (健康数据)
           │
           ▼  (快捷指令 / Health Auto Export 自动上报)
   HTTP POST /health/report (带 X-Auth-Token)
           │
           ▼
 AstrBot 独立接收端口 (:8787)
           │
     ┌─────┴────────────────────────┐
     ▼                              ▼
本地增量存储 (JSON)            主动关怀检测 (Monitor)
     │                              │ (伪造消息注入 Pipeline)
     ▼                              ▼
角色对话读取 (check_health)     小回自然体贴问询
```

## 🚀 部署步骤

> 整个流程 = 【服务器安装与网络放行】+【AstrBot 面板配置】+【手机端数据上报】+【验证】  
> 一次配好，以后全自动静默守护。

### 步骤一（服务器）：安装插件与放行端口

#### 1. 安装插件
- **方式一（推荐）**：WebUI →「插件」→「上传 ZIP」安装。
- **方式二（手动）**：将 `astrbot_plugin_health_bridge/` 文件夹放置在 AstrBot 根目录的 `data/plugins/` 目录下。

#### 2. 防火墙放行端口
接收端默认监听 `8787` 端口，需要在服务器防火墙与云服务商安全组中放行该 TCP 端口：

- **Windows 防火墙命令**（管理员权限 CMD）：
  ```cmd
  netsh advfirewall firewall add rule name="Health Bridge" dir=in action=allow protocol=TCP localport=8787
  ```
- **Linux (UFW) 命令**：
  ```bash
  sudo ufw allow 8787/tcp
  ```
- **云服务器**：别忘了在阿里云/腾讯云/华为云等控制台安全组添加入方向规则：TCP `8787`。

---

### 步骤二（AstrBot 面板）：填配置

进入 AstrBot 管理面板 →「插件」→ `astrbot_plugin_health_bridge` →「配置」：

#### 1. 基础配置

| 配置项 | 说明 | 推荐 / 默认值 |
|---|---|---|
| `auth_token` | 上报接口密钥。**可留空**：首次启动会自动生成专属随机密钥（重载插件后在 WebUI 可见），复制到手机端即可；也可自己填一段长字符串。 | 留空（自动生成） |
| `listen_port` | 独立接收端监听端口。修改后需重启/重载插件。 | `8787` |
| `retention_days` | 历史数据保留天数。超期自动清理，基准以最新数据日期为准。 | `30` |
| `push_target_umo` | 主动关怀推送目标。留空自动寻找最近交互会话；建议填固定私聊会话（如 `default:private:你的QQ`）。 | 留空 或 指定私聊 |

#### 2. 主动关怀配置

| 配置项 | 说明 | 推荐 / 默认值 |
|---|---|---|
| `monitor_enabled` | 主动关怀总开关。建议先用 `/health_monitor test` 验证规则无误后再开。 | `false` |
| `check_interval` | 后台扫描间隔（秒）。 | `900`（15分钟） |
| `baseline_days` | 基线天数：用过去多少天的数据计算「正常均值与标准差」。历史不足 3 天不触发异常。 | `7` |
| `quiet_hours_start` / `quiet_hours_end` | 静默勿扰时段（小时），支持跨天（如 23→7），该时段内绝不打扰。 | `23` / `7` |

填好后保存，并**在插件列表点击「重新加载」**让配置与端口生效。

### 步骤三（手机端）：把数据发出来（任选其一）

接收端同时兼容 **Health Auto Export App** 与 **iOS 自带快捷指令**。二选一配置即可：

---

#### 路线 A：使用 Health Auto Export App（全自动、省心推荐）

App Store 下载 **Health Auto Export – JSON+CSV**。此方式支持后台静默高频率同步（需开启该 App 的 REST API 高级功能）。

##### 1. 新建主自动化（健康指标）
1. 打开 App → 主菜单「自动化 (Automations)」→「新建」→ 类型选 **REST API**。
2. 逐项配置：
   - **URL / 网址**：`http://<服务器公网IP>:8787/health/report`
   - **请求头 (Headers)**：新增键 `X-Auth-Token`，值为插件配置里的 `auth_token`
   - **导出格式**：`JSON`
   - **导出版本**：`v2`
   - **数据类型**：`健康指标`
   - **日期范围**：`今天`（每天上报当天，增量合并）
   - **汇总数据 (Summarize)**：`开启`
   - **时间分组 (Time grouping)**：`天 / Daily`
   - **同步频率**：`1 小时`（推荐值，兼顾实时与续航）
   - **已启用 (Enabled)**：`开启`（⚠️ 务必检查此项）
3. **选择健康指标（点亮 ★）**：
   - 必备推荐：`睡眠分析`、`静息心率`、`心率变异性`、`血氧饱和度`、`呼吸频率`、`Apple 睡眠手腕温度`、`步数`、`活动能量`、`Apple 锻炼时间`、`Apple 站立小时`、`饮水`。
   - 扩展选填：`步行 + 跑步距离`、`已爬楼层`、`步行平均心率`、`体重`、`营养摄入`。

##### 2. 新建辅助自动化（月经周期 / 症状）
经期与症状在 App 里属于独立类型，需分别各建一个 REST API 自动化：
- 网址与 `X-Auth-Token` 请求头保持一致。
- 分别选择数据类型为 **月经周期跟踪** 与 **症状**，频率设为每天或每小时。插件会自动归并到同一天的数据中。

---

#### 路线 B：自己搭 iPhone 快捷指令（免费、原生）

利用 iOS 自带的「快捷指令」与自动化定时触发。

##### 1. 自动化流水线构建：
1. **获取当天日期**：
   - 「当前日期」→「格式化日期」（格式选「自定」，填 `yyyy-MM-dd`）→ 设为变量 `今天日期`。
2. **提取健康样本**：
   - **静息心率 / 血氧 / HRV**：「查找健康样本」→ 选类型，按「开始日期」降序排序，限制 1 条 →「获取详细信息：值」→ 设为变量。
   - **步数 / 饮水**：「查找健康样本」→ 选类型，日期范围选「今天」→「计算统计值（求和）」→ 设为变量。
   - **睡眠**：「查找健康样本：睡眠分析」→「持续时间（秒）」求总和 →「计算 ÷ 60」→ 设为变量 `睡眠分钟`。
3. **POST 发送数据**：
   - 添加「获取 URL 内容」动作：
     - **URL**：`http://<服务器公网IP>:8787/health/report`
     - **方法**：`POST`
     - **请求头**：键 `X-Auth-Token`，值填你的密钥
     - **请求体**：选择 `JSON`，添加对应键值对（`date` 必填，其他根据变量选填）：
       ```json
       {
         "date": "2026-09-14",
         "steps": 6500,
         "resting_hr": 62,
         "blood_oxygen_pct": 98,
         "sleep": { "duration_min": 480 }
       }
       ```
4. **设置自动执行**：
   - 快捷指令 App →「自动化」→ 新建「个人自动化」→ 设定每天定时运行（如早晨起床或晚间解锁手机时）。

---

### 步骤四：验证连接

1. 手机触发一次同步，查看服务器后台日志，应打印：
   ```text
   [health_bridge] 已接收并存储 2026-xx-xx 的数据
   ```
   检查 AstrBot 目录下 `data/plugin_data/astrbot_plugin_health_bridge/` 是否成功生成了对应日期的 `.json` 文件。
2. 在私聊对话中发送调试指令验证：
   ```text
   /health_monitor status    # 查看监控状态、扫描间隔、基线天数
   /health_monitor test      # 模拟执行一次健康扫描，检查异常规则命中与提示词
   ```

## 💬 使用方式

### 方式 A: 角色主动调用 (`check_health`)
小回已挂载该工具。在日常交流中，当你提及疲倦、失眠、运动、或者他关心你时，小回会自然地调取你最近的健康数据（带新鲜度判断），作为了解你状态的基础，绝不会生硬报数字或居高临下说教。

### 方式 B: 后台主动异常关怀 (Monitor)
后台周期性比对健康指标与近期基线，仅在真实检测到生理异常时通过伪造消息注入 Pipeline 发起关怀。

#### 异常监测规则

| 规则 | 触发逻辑 | 默认状态 |
|---|---|---|
| **静息心率偏高** | 相对基线 z-score ≥ `resting_hr_z`（默认 2.0） | ✅ 开启 |
| **睡眠不足** | 睡眠时长比近期基线均值少 ≥ `sleep_short_min`（默认 90 分钟） | ✅ 开启 |
| **血氧偏低** | 低于绝对安全阈值 `spo2_threshold`（默认 95%） | ✅ 开启 |
| **深夜熬夜** | 入睡时间晚于凌晨 `late_night_bedtime_min`（默认 0:30） | ✅ 开启 |
| **HRV 偏低** | 心率变异性相对基线显著下降 | ⚪ 默认关闭（个体差异大） |

> 💡 **冷却保护**：每条关怀规则触发后自带 24 小时独立冷却，避免重复打扰。

#### 关怀提示词 (hint) 设计原则
异常触发时，底层生成的提示是纯粹的客观事实陈述：
- ✅ *「她今天的静息心率 78 bpm，比最近 7 天平均（62 bpm）偏高不少」*
- ✅ *「她昨晚 01:20 才睡，入睡时间偏晚」*
- ❌ ~~*「该睡啦」*~~ ~~*「生病了快吃药」*~~

小回会结合长生者的沉稳、少年感与当下的陪伴氛围自然开口，平视且松弛，绝不爹味说教。

## 🌸 前端看板 (Web Dashboard)

插件内置了轻量化、手机端自适应的健康看板，无需打开管理面板即可随手浏览。

### 打开方式
在局域网或公网浏览器中访问：
```text
http://<服务器IP>:8787/health/dashboard
```

### 页面功能与亮点
- ⏱️ **数据时效显示**：顶部清晰呈现最新数据的同步接收时间（`_received_at`）。
- 🎀 **女性健康卡片**：经期状态、经量等级、生理期记录与周期提醒。
- 📱 **核心健康四宫格**：
  - **心率**：静息心率 + 步行平均心率
  - **血氧**：血氧饱和度百分比
  - **活动**：当日步数、步行里程与爬楼层数
  - **睡眠**：睡眠总时长、入睡/醒来时刻与睡眠分期
- 🌿 **活力时段**：站立活动时段数与中高强度运动时长。
- 🐰 **专属装饰图**：内置兔球球与星际小宝插画相伴。

## 🔒 隐私、安全与特性

- 🛡️ **隔离存储**：数据独立保存在 `<AstrBot>/data/plugin_data/`，更新升级插件永不丢失历史记录。
- 🔑 **防越权与鉴权**：接口强制校验 `X-Auth-Token`；路径与日期经过严格正则防穿越校验；限制 64KB 载荷防止泛洪。
- ⚙️ **低能耗设计**：同日多次上报自动执行轻量增量合并，历史文件定期滚动清理。

## ❓ 常见排查与 FAQ

**Q: 手机上报返回 401？**  
A: 检查手机端请求头中的 `X-Auth-Token` 与 AstrBot 面板中插件配置的 `auth_token` 是否完全一致。

**Q: 手机上报返回 400？**  
A: 检查发送的 JSON 格式是否合规，且必须携带 `YYYY-MM-DD` 格式的 `date` 字段。

**Q: 端口访问超时 / 收不到数据？**  
A: 确认服务器系统防火墙已放行对应端口（默认 8787），若使用云服务器，还需在云控制台放行安全组。

**Q: 主动关怀测试没有发消息？**  
A: 确认会话平台支持 OneBot（aiocqhttp）注入；如非 OneBot 环境，需在配置里明确填写 `push_target_umo`。
